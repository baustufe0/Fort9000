# Forts map plans

Build plans are generated by `tools/fortgen/gen_fort.py` (map config `MAPS`, variants `VARIANTS` for Abyss and
`VANILLA_VARIANTS`) and installed in `fortplans/<Map>/`. Read before changing anything:
- [docs/building-rules.md](../../../docs/building-rules.md) – game mechanics, design rules, validation (always).
- `docs/maps/<map>.md` – the current state of that map's plans, its failed approaches and open problems.
- [docs/generator.md](../../../docs/generator.md) – generator options and "Adding a map" (for a new map).

## Change an existing plan

1. Edit the variant in `gen_fort.py` (plan steps `(kind, [devices])`, kinds `tech`, `eco`, `weapons`, `aa`,
   `defence`, `upgrades`; layout options in its `cfg`). Explain the reason in a comment, like the existing ones.
2. Regenerate into the scratchpad and compare with the installed plans; only the intended plan may change:
   ```bash
   py tools/fortgen/gen_fort.py --maps ../../maps --map Vanilla --out <scratchpad>/gen
   ```
   (Vanilla writes Vanilla-2..5 in order; `--start-number` sets the first number.) Read the output: `ERROR` and
   `RULE ERROR` must be empty; compare `RULE WARN` and notes with the previous run.
3. Install the changed file into `fortplans/<Map>/` (CRLF, header intact; never into `data/maps/`). For a Vanilla
   plan also convert VanillaLong:
   `py tools/fortgen/mid_to_long.py fortplans/Vanilla/fort-t1f1-Vanilla-N.lua ../../ai/forts/vanilla/long/fort-t2f1-Template-1.lua fortplans/VanillaLong/fort-t2f3-VanillaLong-N.lua`
4. Optionally render for a visual check (needs Pillow): `py tools/fortgen/render_all.py ...` (see its docstring) and
   look at the image.
5. Run the tests: `bash tools/tests/run_tests.sh <lua5.1> <Forts>/data` (absolute data path; see CLAUDE.md).
6. Update `docs/maps/<map>.md` (and `docs/building-rules.md` for a new general rule) in the same commit.

## New map

Follow "Adding a map" in docs/generator.md: identify the map and its base plan, add `MAPS["<Map>"]` and a variant
table, generate, check with `rules.py`, render, add a plan-swap test, install, and register the map in
`ai/fortplans.lua` (`Originals`, `OriginalsDir`, `ReactorsPerSide`, `Plans`, optional `Strategy`; see the configuration
reference in [docs/ai.md](../../../docs/ai.md)). Create `docs/maps/<map>.md` and add it to the index in `SPEC.md`.

## Per-map AI settings

`Maps[<Map>].Strategy` in `ai/fortplans.lua` overrides `ai/strategy.lua` on that map only (logged as `MAP-STRATEGY`):
`Tempo`, `Fire`, `Aggression`/`EarlySeconds`/`LateSeconds`, `TargetValue`, `ThreatWeight`, `AntiAirBoostMax`,
`RichMetal`, `PoorMetal`, `BuildSkipSeconds`, `RebuildGiveUpSeconds`. Justify values from the terrain or archived
matches (`tools/logs/`).

## Testing in the game

`Force = { <Map> = "<plan file>" }` in `ai/fortplans.lua` picks a plan for testing; never commit it (stage only other
changes). After the match, use the `forts-match-review` skill.

## Report

English, short: what changed in which plan and why, generator/rules output, tests, what to watch in the next match
(`PLAN map=<Map> file=...`, `BUILD_ERROR`, `GAVE_UP`), and that only real matches show whether a plan holds.
